# Changelog

All notable changes to this project are listed here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Removed
- The UnrealPak response-file packer path of `pakmod.py` and its config keys `packer` and `packer_args` (spec 09 uses repak and UAssetGUI).

### Changed
- Run cap (spec 10, U3): the default cap of `run.py` is now 400 runs (it was 100). The environment variable `HARNESS_MAX_RUNS` changes the default, `--max-runs` still wins, and a bad value fails with a clear message. `runs/.iterations` is kept. The MCP tool `game_status` uses the same default.
- Asset mods (spec 09), first real spike: repak 0.2.3 and UAssetGUI 1.1.0 work on the real game. `pakmod.py` config key `usmap_name` (UAssetGUI 1.1.0 reads a mapping by name from its Mappings folder; `check` and every convert compare that file with the `.usmap`), default `engine_version` `VER_UE5_5`, and `tojson` fails loudly when UAssetGUI writes a `RawExport`. Notes: `docs/specs/09-asset-mods/implementation-notes/pak-spike-findings.md` and `docs/specs/10-invasion-testability/implementation-notes/game-data-tables.md` (names of the game data tables).
- Mod-state contract (spec 10, U10): each mod now serves its own commands and metrics in its own Lua state. The first `HarnessCommands.register` or `HarnessCommands.metric` in a mod starts a poller for `<run>/modcmd/<ModName>/<number>.json`. New `HarnessCommands.metric(name, fn)` and built-in commands `harness.metrics` and `harness.list_commands` (per mod). Python: `ModCommandChannel` and `ModDidNotAnswer` in `runlib/commands.py`; `ctx.mod.commands(mod)` takes the mod name, `ctx.mod.metric/wait_metric` read through `harness.metrics` (always current, no longer from `telemetry.jsonl`), `metrics_window` returns the reads of the scenario (`t`, `values`), new `ctx.mod_commands`. `HarnessActions` no longer relays dotted commands (version 5). `InvasionStandIn` version 2 uses `HarnessCommands.metric`. `HarnessLog.make_dir`. Fake game kit: `FakeGame(separate_states=True)` runs each mod in its own Lua state, and `game.exec(code, state=...)`. Notes: `docs/specs/10-invasion-testability/implementation-notes/mod-state-contract.md`.

### Fixed
- Mod commands failed with `unknown command` in the real game because UE4SS gives each mod its own Lua state, so the registry in `HarnessCommands` was not shared (real run `20261010-172028-008b`). See Changed. Not yet verified in the real game.

### Changed
- The scenario limit cap in the scenario test is now 300 s (was 120 s), for the raid scenarios of spec 10.
- The preflight no longer fails when Steam is not running. The direct launch works without Steam (tested), so it only adds a note to the summary. `.claude/settings.json`: `run_scenario` is allowed without asking, by the user's decision.
- `HarnessBoot` waits for the end of the intro cinematic (`PawnCPP.currentUIMode ~= 0`) before it calls `pauseGame`, so the game does not undo the pause. One `pauseGame` call in each boot (5 of 5 smoke runs, before: two); the 8 s hold stays as a safety net.
- Fake clock: `late_revert_after` is off by default (the intro cinematic is the default restart).
- `summary.json` is smaller: it drops empty fields, keeps only the seconds of good phases, and has a short environment (the full mod hashes are in `config.json`). Assertion records use `rule` instead of `range`.
- Vendored bridge: raw Lua eval is off by default, and it is gated in the Python server too.
- Vendored bridge: the bridge folder follows `HARNESS_RUN_DIR`.
- MCP dependencies are locked with hashes (`mcp/requirements.in` and `mcp/requirements.txt`) and installed with uv.

### Fixed
- The command channel retries when the mod still holds a result file open (Windows `PermissionError`) or has written only part of it. A run of 120 reads failed with `PermissionError` before.
- Crash reports were never copied: the UE crash handler writes into the user's real `Crashes` folder, not the private `LOCALAPPDATA`. `collect` now searches both folders and matches the process id. `teardown` stops the `CrashReportClient.exe` that a crash leaves open.
- `--keep-open` now prints how to stop the game and delete the private appdata, and says that the user's save files were not compared.
- Vendored bridge: the poller no longer stays busy forever after a failed reply. Large responses and limits are capped. `dump` needs `allow_writes`.
- Vendored bridge: a nil property or function name no longer crashes the game. It returns an error.
