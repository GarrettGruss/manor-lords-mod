### Changed
- Soak (#53): `soak-days` accepts up to 13000 s of wall time (`MAX_LIMIT_S` 13500 s) and wider clock-rate (1.5 to 9) and days (0.2 to 1.1) ranges. A 3.3 h run reached day 333 of 730 with no crash and no memory growth; see spec 10 `open-items.md`.

### Fixed
- Spec 11: sessions in git worktrees share the game slots, run locks, start claims, run counter, fixture ledger, input lock and save backups with the main checkout (`runlib/shared.py`). Before, a worktree saw only slot 0 and none of the other sessions' locks. `install.ps1` and `uninstall.ps1` use the main checkout's `slots` from a worktree too. Skill `harness-dispatch-agents`: up to 3 agents may use the game, one per slot.
- Spec 11: parallel games no longer read the save list at the same time (the launch holds `runs/.saves.lock` until the main menu); before, two of three games saw only `autosave`. Lock files survive the Windows delete race (`PermissionError`). Preflight, launch and teardown limits include the lock wait (`RUN_OVERHEAD_S` 1200 s). The bridge client checks the run's own game pid (`UE4SS_BRIDGE_GAME_PID`) instead of `tasklist`, which reported a live game as gone under load.
- The `test_pakmod` uninstall tests used the real `slots` folder, so the full suite could delete the real slots. They use a temp folder now, and `uninstall.ps1` leaves an install state of another game folder alone.
- Time control (#143): a run of `ctx.time` calls the pop-up guard (`ctx.popups`) every 2 s. A "Hunger!" pop-up that opened in a chunk of 10 game days paused the game for the rest of the chunk and failed a 120-day run.
- genmesh (#131, #102): the Meshy task id is written to the spend log at creation, before polling, so a client timeout cannot lose it. New command `resume --task <id> --out <dir>` downloads an existing task and spends no credits.
- Harness: the default placement click point is now (0.35, 0.3). The old point (0.65, 0.65) lay over the sawpit in fixture `base`, so the ghost was blocked (run 20261015-203710-6b45).
- HarnessPlace: remove the `pivot_attach` and `pivot_move` commands. `pivot_attach` passed a Lua string as an FName and crashed the game in UE4SS `push_nameproperty`.
- Real-mouse input (#115): `osinput` now fails at once with "no mouse device" when Windows reports no mouse (`SM_MOUSEPRESENT` 0). That state made `getMouse3d` return Z -100000 and blocked every real placement click. New tools `s115_input_env.py` and `s115_probe.py`; note `os-mouse-regression.md`. The placement itself still needs a mouse on the PC.

### Changed
- The scenario limit cap in the scenario test is now 300 s (was 120 s), for the raid scenarios of spec 10.
- The preflight no longer fails when Steam is not running. The direct launch works without Steam (tested), so it only adds a note to the summary. `.claude/settings.json`: `run_scenario` is allowed without asking, by the user's decision.
- `HarnessBoot` waits for the end of the intro cinematic (`PawnCPP.currentUIMode ~= 0`) before it calls `pauseGame`, so the game does not undo the pause. One `pauseGame` call in each boot (5 of 5 smoke runs, before: two); the 8 s hold stays as a safety net.
- Fake clock: `late_revert_after` is off by default (the intro cinematic is the default restart).
- `summary.json` is smaller: it drops empty fields, keeps only the seconds of good phases, and has a short environment (the full mod hashes are in `config.json`). Assertion records use `rule` instead of `range`.
- Vendored bridge: raw Lua eval is off by default, and it is gated in the Python server too.
- Vendored bridge: the bridge folder follows `HARNESS_RUN_DIR`.
- MCP dependencies are locked with hashes (`mcp/requirements.in` and `mcp/requirements.txt`) and installed with uv.

### Fixed
- The command channel retries when the mod still holds a result file open (Windows `PermissionError`) or has written only part of it. A run of 120 reads failed with `PermissionError` before.
- Crash reports were never copied: the UE crash handler writes into the user's real `Crashes` folder, not the private `LOCALAPPDATA`. `collect` now searches both folders and matches the process id. `teardown` stops the `CrashReportClient.exe` that a crash leaves open.
- `--keep-open` now prints how to stop the game and delete the private appdata, and says that the user's save files were not compared.
- Vendored bridge: the poller no longer stays busy forever after a failed reply. Large responses and limits are capped. `dump` needs `allow_writes`.
- Vendored bridge: a nil property or function name no longer crashes the game. It returns an error.
